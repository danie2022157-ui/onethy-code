# Code Review

## Purpose
Catch correctness, design, and maintainability problems before integrating changes.

## When to use
When reviewing a significant diff or responding to requested review.

## Core steps
1. Check the diff against requirements and acceptance criteria.
2. Look for correctness, security, regressions, complexity, and missed tests.
3. Verify claims with code and focused checks where possible.
4. Report actionable findings by severity, with file/line context.
5. Separate true blockers from preferences.
