# PR

## Purpose
Deliver a change in a pull request that reviewers can confidently approve.

## When to use
When a verified branch is ready to merge into the integration branch.

## Core steps
1. Confirm tests and relevant package checks pass.
2. Summarize the change, rationale, and user-facing behavior.
3. Target the repository's base branch (for this repo, `dev`).
4. Include test evidence and any notable limitations.
5. Keep the diff focused; do not commit unrelated modifications.
