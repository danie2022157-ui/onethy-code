# To Spec

## Purpose
Capture agreed requirements as a concise specification an engineer can implement.

## When to use
After requirements have been clarified and before planning or implementation.

## Core steps
1. Summarize intent, scope, non-goals, and user-visible behavior.
2. Enumerate constraints, dependencies, and important edge cases.
3. Define acceptance criteria and verification requirements.
4. Link to the issue tracker when configured; otherwise keep the spec local and minimal.
5. Ask the user to confirm or correct the spec before coding.
