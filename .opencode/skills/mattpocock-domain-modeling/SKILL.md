# Domain Modeling

## Purpose
Clarify domain entities, relationships, and invariants before coding.

## When to use
When business rules, terminology, or data relationships are ambiguous.

## Core steps
1. Extract domain terms from the spec or user conversation.
2. Define entities, their attributes, and relationships.
3. Identify invariants and constraints that must hold.
4. Map domain concepts to code structures (types, modules, validation).
5. Use domain terms consistently in naming and documentation.
