# Prototype

## Purpose
Validate a technical approach cheaply before full implementation.

## When to use
When the feasibility or design of a feature is uncertain.

## Core steps
1. Set a clear, time-boxed question for the prototype.
2. Implement a minimal, throwaway version in a scratch area or worktree.
3. Evaluate results honestly; discard if the approach is unsuitable.
4. Hand off validated insights into implementation with TDD.
